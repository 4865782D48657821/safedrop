# Delivery Workflow

1. Discover repository commands, tests, linting, build steps, and local conventions.
2. Preserve unrelated user changes and avoid formatting churn.
3. Define the intended change, affected files, verification scope, and rollback considerations when relevant.
4. Implement with the narrowest viable edit.
5. Verify locally with commands proportional to risk.
6. Review independently when required.
7. Fix confirmed issues, rerun relevant checks, and report remaining gaps.

Do not route every task through every role. Additional roles must reduce risk or improve evidence.
