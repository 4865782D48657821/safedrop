# Analyze Requirements

## Required Inputs

- Request, stakeholders or users, current system context, constraints, and deadlines if known.

## Workflow

1. Classify requirement types using `references/requirement-types.md`.
2. Check ambiguity with `references/ambiguity-checklist.md`.
3. Distinguish facts, assumptions, open questions, and decisions.
4. Use `assets/requirements-template.md` for structured output when requirements must be handed off.
5. Stop if missing requirements affect safety, security, compliance, data integrity, or major architecture.

## Expected Result

Produce a concise requirements analysis with clarified scope, risks, acceptance signals, and blockers.
