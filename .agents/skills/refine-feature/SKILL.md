# Refine Feature

## Required Inputs

- User goal, target users, affected workflows, constraints, and known non-goals.

## Workflow

1. Separate facts, assumptions, open questions, and decisions.
2. Use `references/refinement-checklist.md` to identify missing scope, edge cases, states, and dependencies.
3. Use `references/requirement-quality.md` to make requirements testable.
4. Capture the result with `assets/feature-brief-template.md` or `assets/acceptance-criteria-template.md` when useful.
5. Stop if unresolved ambiguity changes security, data, architecture, cost, or user-visible behavior materially.

## Expected Result

Produce implementation-ready requirements with acceptance criteria, non-goals, risks, and explicit open questions.
